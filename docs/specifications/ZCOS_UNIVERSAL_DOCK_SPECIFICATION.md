# ZCOS Universal Dock Specification

**Status:** Locked for implementation — dock baseline amended  
**Version date:** August 11, 2026  
**Scope:** Eight galaxy Consoles, their Docks, and Desk-control mapping

> **Governing rule:** Every galaxy Console has one five-button Dock. Chat and Upload are universal. The remaining three buttons are the direct controls of that galaxy's specialized Desk. History is universal but is not a Dock button.

## 1. Purpose and boundary

This specification supersedes the older six-button Dock baseline and locks one consistent action model across all eight galaxies. It defines button count, order, universal behavior, Desk-control labels, and the relationship between Dock and History.

The Dock amendment does not alter the eight-galaxy architecture, seven shared domains, unified Identity, universal ZCOS authentication, central Memory and Knowledge authorities, Admin Access, Portal, Project ownership, Personal Files Authority, or approved visual design.

## 2. Universal Dock contract

| Rule | Contract |
| --- | --- |
| Button count | Exactly five primary buttons appear in every Dock. |
| Fixed controls | Chat is first and Upload is second in every Dock. |
| Desk controls | Buttons three through five correspond to the three specialized Desk controls. |
| Chat | Opens the persistent line to the same ZAR identity while retaining active galaxy and Desk context. |
| Upload | Opens one branching intake for image, document, and other file choices; type is selected after tapping Upload. |
| History | Available in every Console as a universal option outside the five-button Dock count. History is not automatically Memory. |
| Visual contract | Approved Dock appearance, spacing, styling, hierarchy, motion, and touch behavior remain unchanged unless separately authorized. |
| Truthful capability | A control appears operational only when route, permission, error state, recovery path, and applicable certification are real. |

## 4. Shared controls and options

### Chat

Universal first button. Opens ZAR in the current galaxy context. Talk and SMS are ZAR communication modes, not separate universal Dock buttons.

### Upload

Universal second button. Opens a source/type chooser for image, document, and other file intake. Upload does not automatically authorize Memory, Knowledge, Glow, Library placement, public sharing, or cross-galaxy use.

### History

Universal Console option outside the five Dock buttons. Shows relevant prior activity without becoming a Desk control or Memory authority.

## 5. Desk control contracts

### 5.1 ZAR NEXYS — Operate

Dock: **Chat · Upload · Ideas · Task · Search**

- **Ideas** — generate and develop possibilities within the active context.
- **Task** — plan, execute, verify, and track authorized work.
- **Search** — search authorized web and ZCOS sources for evidence, records, and prior context.

### 5.2 ZYNC CANVAS — Build

Dock: **Chat · Upload · Code · Design · Publish**

- **Code** — create and work with websites, applications, components, and technical systems.
- **Design** — create and work with interfaces, graphics, layouts, mockups, and visual assets.
- **Publish** — preview, package, export, deploy, or release completed work.

### 5.3 ZETA CONTROL — Integrity

Dock: **Chat · Upload · Logs · Diagnostics · Monitoring**

- **Logs** — open recorded system events and integrity evidence.
- **Diagnostics** — run or review authorized system checks and findings.
- **Monitoring** — view current health, alerts, and tracked system conditions.

### 5.4 ZWAP! DISCOVERY — Explore

Dock: **Chat · Upload · Glow · Move · Play**

- **Glow** — review what ZAR has compiled about the user through the authorized Glow process.
- **Move** — activate movement tracking.
- **Play** — open and play a game.

### 5.5 ZENO UNITE — Forum

Dock: **Chat · Upload · Board · Team · Notes**

- **Board** — open the Forum board.
- **Team** — open the team space.
- **Notes** — open and manage notes.

### 5.6 ZYLO COMPASS — Automate

Dock: **Chat · Upload · Flows · Skills · Tips**

- **Flows** — build and manage automations; templates and execution records remain within Flows.
- **Skills** — manage reusable capabilities that equip and support Flows.
- **Tips** — review automation opportunities ZYLO identifies and recommends.

### 5.7 ZENITH LOGOS — Scholar

Dock: **Chat · Upload · Files · Study · Library**

- **Files** — access and manage owned files and intentional Scholar file placements.
- **Study** — open the learning and study environment.
- **Library** — open the organized learning/reference collection.

### 5.8 ZILLION PROSPER — Capital

Dock: **Chat · Upload · Budget · Trade · Invest**

- **Budget** — open budgeting and financial planning.
- **Trade** — open trading tools and activity, subject to authorization and certification.
- **Invest** — open investing tools, holdings, and long-term capital activity.

## 6. Supersession map

- Prior universal six-button Dock drafts are superseded.
- Image and Document branch from Upload.
- Talk and SMS remain ZAR communication modes rather than universal Dock buttons.
- ZAR Operate's earlier Support / Brainstorm-Research / Tasks presentation maps to Ideas / Task / Search at the Dock layer; Chat carries support and Search carries research.
- ZYNC Coding / Design / Publish becomes Code / Design / Publish.
- ZETA Logs / Diagnostics / Monitoring remains unchanged.
- ZWAP! Glow / News / Journal-Blog becomes Glow / Move / Play at the Dock layer.
- ZENO Threads / Notes / Rooms becomes Board / Team / Notes.
- ZYLO Flows-Loops / Skills / Templates becomes Flows / Skills / Tips; templates remain inside Flows.
- ZENITH Learning Studio / Library / Files becomes Files / Study / Library.
- ZILLION Budgeting / Trading / Investing becomes Budget / Trade / Invest.

## 7. Acceptance

- Every Console renders exactly five primary Dock buttons in the specified order.
- Chat and Upload behave consistently while retaining galaxy/Desk context.
- Upload branches to file/source type instead of restoring separate Image/Document buttons.
- History appears in every Console outside the five-button Dock.
- Each specialized button opens the assigned Desk function.
- Approved visual design is preserved.
- Blocked, partial, unavailable, and uncertified states are represented truthfully.
